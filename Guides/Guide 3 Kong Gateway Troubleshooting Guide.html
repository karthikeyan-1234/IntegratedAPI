Quick Diagnostic Checklist

Purpose: This guide addresses common issues encountered when configuring Kong Gateway with HTTPS on Docker Desktop Kubernetes. Solutions are based on real troubleshooting sessions.

System Health Checklist

  • ✅ Kong pods running in kong namespace
  • ✅ Application pods running in default namespace
  • ✅ Certificates created and ready in kong namespace
  • ✅ Ingress configured with correct hostnames
  • ✅ Services registered in Kong
  • ✅ Routes created with correct paths
  • ✅ No conflicting ingress rules

Issue: 503 Service Temporarily Unavailable

Symptom: Accessing https://kong-proxy.local/web or other routes returns 503 error from nginx.

1.1 Root Cause: Conflicting Ingress Rules

The Problem: Multiple ingress resources with the same hostname cause the nginx ingress controller to route traffic incorrectly. If you have an old ingress pointing directly to your application, it intercepts requests before they reach Kong.

Check for Conflicting Ingress Rules PowerShell / Bash
# Check for conflicting ingress rules kubectl get ingress --all-namespaces # Look for multiple ingresses with the same host # Example conflict: # default angular-web-ingress nginx kong-proxy.local <- CONFLICT! # kong kong-proxy-ingress nginx kong-proxy.local <- CONFLICT!

Diagnosis

Check Ingress Controller Logs PowerShell / Bash
# Check nginx ingress controller logs kubectl get pods -n ingress-nginx kubectl logs -n ingress-nginx <ingress-controller-pod> --tail=50 # Look for routing to wrong backend: # "GET /web HTTP/2.0" 503 ... [default-angular-app-80] [] - - - - # Should be: [kong-kong-proxy-80] [] 10.244.3.18:8000

Solution

Fix Conflicting Ingress PowerShell / Bash
# Delete conflicting ingress in default namespace kubectl delete ingress angular-web-ingress -n default # Verify only Kong ingresses remain kubectl get ingress --all-namespaces # Test again Invoke-WebRequest -Uri "https://kong-proxy.local/web" -SkipCertificateCheck

1.2 Root Cause: Service Not Registered in Kong

The Problem: Kong cannot route traffic if the service hasn't been registered via the Admin API.

Diagnosis

Check Service Registration PowerShell
# Check if service exists in Kong Invoke-RestMethod -Uri "https://kong-admin.local/services" -SkipCertificateCheck # Check Kong logs (no requests reaching Kong proxy) kubectl logs -n kong deployment/kong --tail=20 # If logs show only Admin API requests but no proxy requests, # the traffic isn't reaching Kong

Solution

Register Missing Service PowerShell
# Register the missing service (example: Angular app) Invoke-RestMethod -Uri "https://kong-admin.local/services/" ` -Method POST ` -ContentType 'application/json' ` -Body (@{ name = "angular-app-service" url = "http://angular-app-service.default.svc.cluster.local:80" } | ConvertTo-Json) ` -SkipCertificateCheck # Create route for the service Invoke-RestMethod -Uri "https://kong-admin.local/services/angular-app-service/routes" ` -Method POST ` -ContentType 'application/json' ` -Body (@{ name = "angular-app-route" paths = @("/web", "/web/") strip_path = $true preserve_host = $true } | ConvertTo-Json) ` -SkipCertificateCheck

1.3 Root Cause: Wrong Service Port Configuration

The Problem: Kong service configured with wrong port (e.g., port 7080 for Angular when it should be 80).

Diagnosis

Check Service Configuration PowerShell
# Check service configuration Invoke-RestMethod -Uri "https://kong-admin.local/services/angular-app-service" -SkipCertificateCheck # Look for incorrect port: # "port": 7080 <- WRONG for Angular (nginx runs on port 80) # "port": 80 <- CORRECT for Angular # Verify actual Kubernetes service port kubectl get svc angular-app-service # Should show: PORT(S) 80/TCP

Solution

Update Service Port PowerShell
# Update service with correct port Invoke-RestMethod -Uri "https://kong-admin.local/services/angular-app-service" ` -Method PATCH ` -ContentType 'application/json' ` -Body (@{port = 80} | ConvertTo-Json) ` -SkipCertificateCheck # Verify the change Invoke-RestMethod -Uri "https://kong-admin.local/services/angular-app-service" -SkipCertificateCheck

1.4 Root Cause: Upstream Service Not Reachable

The Problem: Kong cannot connect to the upstream service (application pods not running or service misconfigured).

Diagnosis

Check Application Health PowerShell / Bash
# Check if application pods are running kubectl get pods -l app=angular-app kubectl get pods -l app=integratedapi # Check if services have endpoints kubectl get endpoints angular-app-service kubectl get endpoints integratedapi-service # If no endpoints, pods might not match service selector kubectl describe svc angular-app-service # Test connectivity directly to the service kubectl port-forward svc/angular-app-service 8888:80 # Then test: http://localhost:8888

Solution

Fix Service Connectivity PowerShell / Bash
# If pods aren't running, check deployment kubectl get deployment angular-app-deployment kubectl describe deployment angular-app-deployment # If service has no endpoints, check selector labels kubectl get deployment angular-app-deployment -o yaml | grep -A5 labels kubectl get svc angular-app-service -o yaml | grep -A5 selector # Ensure labels match between deployment and service

Issue: Angular App Assets Return 404

Symptom: Angular app loads but JavaScript/CSS files return 404 errors. Browser console shows: Failed to load resource: main.js 404 Not Found

Root Cause: Incorrect strip_path Setting

The Problem: Angular app built with <base href="/web/"> requires strip_path = true in Kong route.

Diagnosis

Check Route Configuration PowerShell
# Check route configuration Invoke-RestMethod -Uri "https://kong-admin.local/routes/angular-app-route" -SkipCertificateCheck # Look for: # "strip_path": false <- WRONG for Angular with base href="/web/" # "strip_path": true <- CORRECT # Port forward directly to pod to verify files exist kubectl port-forward angular-app-deployment-xxxxx 8888:80 # Then test: http://localhost:8888/main.js (should work)

Understanding strip_path

Browser Requests strip_path = false strip_path = true
/web/main.js Kong forwards /web/main.js
Nginx looks for /usr/share/nginx/html/web/main.js
❌ 404 Not Found		 Kong forwards /main.js
Nginx looks for /usr/share/nginx/html/main.js
✅ 200 OK

Solution

Fix strip_path Setting PowerShell
# Update route with strip_path = true Invoke-RestMethod -Uri "https://kong-admin.local/routes/angular-app-route" ` -Method PATCH ` -ContentType 'application/json' ` -Body (@{strip_path = $true} | ConvertTo-Json) ` -SkipCertificateCheck # Or delete and recreate the route Invoke-RestMethod -Uri "https://kong-admin.local/routes/angular-app-route" ` -Method DELETE ` -SkipCertificateCheck Invoke-RestMethod -Uri "https://kong-admin.local/services/angular-app-service/routes" ` -Method POST ` -ContentType 'application/json' ` -Body (@{ name = "angular-app-route" paths = @("/web", "/web/") strip_path = $true preserve_host = $true } | ConvertTo-Json) ` -SkipCertificateCheck

Issue: Certificate Errors in Browser

Symptom: Browser shows "Your connection is not private" or "NET::ERR_CERT_AUTHORITY_INVALID"

Root Cause: Self-Signed Certificate Not Trusted

Diagnosis

Check Certificates PowerShell / Bash
# Check if certificates are created kubectl get certificates -n kong kubectl get secrets -n kong | grep tls # Verify certificate is being used by ingress kubectl describe ingress kong-proxy-ingress -n kong

Solution

Trust Root CA Certificate PowerShell / Bash
# Export and trust the root CA certificate kubectl get secret local-dev-root-ca -n cert-manager -o jsonpath='{.data.ca\.crt}' | base64 -d > local-dev-root-ca.crt # Windows: Install Certificate # 1. Double-click local-dev-root-ca.crt # 2. Click "Install Certificate" # 3. Choose "Local Machine" # 4. Select "Trusted Root Certification Authorities" # 5. Complete wizard # 6. Restart browser # Alternatively: Use -SkipCertificateCheck in PowerShell Invoke-WebRequest -Uri "https://kong-proxy.local/web" -SkipCertificateCheck

Issue: PowerShell -SkipCertificateCheck Not Recognized

Symptom: A parameter cannot be found that matches parameter name 'SkipCertificateCheck'

Root Cause: Using Old PowerShell Version

Solution

Fix PowerShell Version PowerShell
# Option 1: Upgrade to PowerShell 7+ winget install --id Microsoft.Powershell --source winget # Close and reopen terminal, then launch: pwsh # Not 'powershell' # Option 2: Bypass certificate validation in Windows PowerShell 5.1 add-type @" using System.Net; using System.Security.Cryptography.X509Certificates; public class TrustAllCertsPolicy : ICertificatePolicy { public bool CheckValidationResult( ServicePoint svcPoint, X509Certificate certificate, WebRequest request, int certificateProblem) { return true; } } "@ [System.Net.ServicePointManager]::CertificatePolicy = New-Object TrustAllCertsPolicy [System.Net.ServicePointManager]::SecurityProtocol = [System.Net.SecurityProtocolType]::Tls12 # Now use Invoke-RestMethod without -SkipCertificateCheck parameter

Issue: Kong Admin API Not Accessible

Symptom: https://kong-admin.local returns connection error or 502/503

Diagnosis

Check Kong Admin Health PowerShell / Bash
# Check Kong pods are running kubectl get pods -n kong # Check Kong admin service kubectl get svc -n kong kong-admin # Check ingress for admin kubectl get ingress -n kong kong-admin-ingress kubectl describe ingress kong-admin-ingress -n kong # Check Kong logs kubectl logs -n kong deployment/kong --tail=50 # Test admin API directly via port-forward kubectl port-forward -n kong svc/kong-admin 8001:8001 # Then test: http://localhost:8001/status

Solution

Fix Admin API Access PowerShell / Bash
# If ingress is missing, create it (see Guide 1) # If certificate is missing, create it (see Guide 1) # Verify admin service ports kubectl get svc -n kong kong-admin # Should show: 8001/TCP # Check hosts file # Windows: C:\Windows\System32\drivers\etc\hosts # Should contain: 127.0.0.1 kong-admin.local

Diagnostic Commands Reference

Quick Health Check

# Check all components at once kubectl get pods --all-namespaces | grep -E 'kong|cert-manager|ingress-nginx|angular|integrated' kubectl get svc --all-namespaces | grep -E 'kong|angular|integrated' kubectl get ingress --all-namespaces kubectl get certificates -n kong

Kong Specific

# Kong status Invoke-RestMethod -Uri "https://kong-admin.local/status" -SkipCertificateCheck # List all services Invoke-RestMethod -Uri "https://kong-admin.local/services" -SkipCertificateCheck # List all routes Invoke-RestMethod -Uri "https://kong-admin.local/routes" -SkipCertificateCheck # Check Kong logs kubectl logs -n kong deployment/kong --tail=50 --follow

Ingress Controller

# Get ingress controller pod kubectl get pods -n ingress-nginx # Check ingress controller logs kubectl logs -n ingress-nginx deployment/ingress-nginx-controller --tail=50 # Look for routing decisions in logs: # [kong-kong-proxy-80] = Correct (routed to Kong) # [default-angular-app-80] = Wrong (bypassing Kong)

Network Connectivity

# Test direct pod access kubectl port-forward -n kong deployment/kong 8000:8000 # Then test: http://localhost:8000/web # Test service connectivity from within cluster kubectl run test-pod --image=busybox --rm -it --restart=Never -- wget -O- http://angular-app-service.default.svc.cluster.local:80 # Check service endpoints kubectl get endpoints angular-app-service kubectl get endpoints integratedapi-service

Troubleshooting Workflow

Step-by-Step Diagnostic Process

    Identify the symptom: 503? 404? Certificate error? Connection refused?
    Check the basics: Pods running? Services have endpoints? Ingress configured?
    Review Kong configuration: Service registered? Route created? Correct settings?
    Check for conflicts: Multiple ingresses with same host? Wrong ports?
    Test incrementally: Port-forward → Service → Ingress → Kong → Full path
    Review logs: Kong logs, ingress controller logs, application logs

Related Guides

  • Guide 1: Kong HTTPS Setup (certificate and ingress configuration)
  • Guide 2: Configuring Applications (service and route registration)
  • Kong Documentation: https://docs.konghq.com/gateway/latest/

Prevention Tips

  • Always check for conflicting ingresses before creating new ones
  • Verify service ports match actual application ports (80 for nginx, 7080 for API, etc.)
  • Use strip_path = true for Angular apps with base href
  • Test with port-forward first to isolate issues
  • Check ingress controller logs to see actual routing decisions
  • Use PowerShell 7+ for better HTTPS testing support
