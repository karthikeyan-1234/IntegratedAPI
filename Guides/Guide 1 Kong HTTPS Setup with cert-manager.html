Architecture Overview

System Components

  • Kong Gateway: Admin (8444), Proxy (8443), Manager (8445)
  • cert-manager: Automated certificate lifecycle management
  • Self-signed CA: Local development certificate authority
  • NGINX Ingress: TLS termination and routing
Objective: Configure Kong Gateway with HTTPS using cert-manager and self-signed certificates for local development on Docker Desktop Kubernetes.
2

Install cert-manager

Terminal Command PowerShell / Bash
# Install cert-manager v1.12.0 kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.12.0/cert-manager.yaml # Verify installation (wait for all pods to be Running) kubectl get pods -n cert-manager # Expected output: cert-manager, cert-manager-cainjector, cert-manager-webhook
3

Create Certificate Authority

3.1 Self-Signed ClusterIssuer

selfsigned-cluster-issuer.yaml Kubernetes Manifest
apiVersion: cert-manager.io/v1 kind: ClusterIssuer metadata: name: selfsigned-cluster-issuer spec: selfSigned: {}
Apply Configuration PowerShell / Bash
kubectl apply -f selfsigned-cluster-issuer.yaml

3.2 Root CA Certificate

root-ca.yaml Kubernetes Manifest
apiVersion: cert-manager.io/v1 kind: Certificate metadata: name: root-ca namespace: cert-manager spec: isCA: true commonName: local-dev-root-ca secretName: local-dev-root-ca duration: 87600h # 10 years renewBefore: 720h # 30 days issuerRef: name: selfsigned-cluster-issuer kind: ClusterIssuer
Apply Configuration PowerShell / Bash
kubectl apply -f root-ca.yaml

3.3 CA ClusterIssuer

ca-cluster-issuer.yaml Kubernetes Manifest
apiVersion: cert-manager.io/v1 kind: ClusterIssuer metadata: name: local-ca-cluster-issuer spec: ca: secretName: local-dev-root-ca
Apply and Verify PowerShell / Bash
kubectl apply -f ca-cluster-issuer.yaml # Verify ClusterIssuer is ready kubectl get clusterissuer
4

Generate Certificates for Kong

Note: Create separate certificates for each Kong service endpoint.
kong-certificates.yaml Kubernetes Manifest
apiVersion: cert-manager.io/v1 kind: Certificate metadata: name: kong-proxy-tls namespace: kong spec: secretName: kong-proxy-tls issuerRef: name: local-ca-cluster-issuer kind: ClusterIssuer dnsNames: - kong-proxy.local --- apiVersion: cert-manager.io/v1 kind: Certificate metadata: name: kong-admin-tls namespace: kong spec: secretName: kong-admin-tls issuerRef: name: local-ca-cluster-issuer kind: ClusterIssuer dnsNames: - kong-admin.local --- apiVersion: cert-manager.io/v1 kind: Certificate metadata: name: kong-ui-tls namespace: kong spec: secretName: kong-ui-tls issuerRef: name: local-ca-cluster-issuer kind: ClusterIssuer dnsNames: - kong-ui.local - kong-manager.local
Apply and Verify Certificates PowerShell / Bash
kubectl apply -f kong-certificates.yaml # Verify certificates are ready kubectl get certificates -n kong kubectl get secrets -n kong | grep tls
5

Configure Ingress for HTTPS

kong-ingress.yaml Kubernetes Manifest
apiVersion: networking.k8s.io/v1 kind: Ingress metadata: name: kong-proxy-ingress namespace: kong annotations: cert-manager.io/cluster-issuer: local-ca-cluster-issuer nginx.ingress.kubernetes.io/ssl-redirect: "true" spec: ingressClassName: nginx tls: - hosts: - kong-proxy.local secretName: kong-proxy-tls rules: - host: kong-proxy.local http: paths: - path: / pathType: Prefix backend: service: name: kong-proxy port: number: 80 --- apiVersion: networking.k8s.io/v1 kind: Ingress metadata: name: kong-admin-ingress namespace: kong annotations: cert-manager.io/cluster-issuer: local-ca-cluster-issuer nginx.ingress.kubernetes.io/ssl-redirect: "true" spec: ingressClassName: nginx tls: - hosts: - kong-admin.local secretName: kong-admin-tls rules: - host: kong-admin.local http: paths: - path: / pathType: Prefix backend: service: name: kong-admin port: number: 8001 --- apiVersion: networking.k8s.io/v1 kind: Ingress metadata: name: kong-ui-ingress namespace: kong annotations: cert-manager.io/cluster-issuer: local-ca-cluster-issuer nginx.ingress.kubernetes.io/ssl-redirect: "true" spec: ingressClassName: nginx tls: - hosts: - kong-ui.local secretName: kong-ui-tls rules: - host: kong-ui.local http: paths: - path: / pathType: Prefix backend: service: name: kong-manager port: number: 8002
Apply Ingress Configuration PowerShell / Bash
kubectl apply -f kong-ingress.yaml # Verify ingress configuration kubectl get ingress -n kong kubectl describe ingress kong-proxy-ingress -n kong
6

Configure Local DNS

Hosts File Configuration System Configuration
# Windows: C:\Windows\System32\drivers\etc\hosts (Run as Administrator) # Linux/Mac: /etc/hosts 127.0.0.1 kong-proxy.local 127.0.0.1 kong-admin.local 127.0.0.1 kong-ui.local 127.0.0.1 kong-manager.local
7

Trust Root CA Certificate (Optional)

Note: This step eliminates browser security warnings for self-signed certificates.
Export and Install Root CA PowerShell / Bash
# Export root CA certificate kubectl get secret local-dev-root-ca -n cert-manager -o jsonpath='{.data.ca\.crt}' | base64 -d > local-dev-root-ca.crt # Windows: Import Certificate # 1. Double-click local-dev-root-ca.crt # 2. Click "Install Certificate" # 3. Choose "Local Machine" # 4. Select "Trusted Root Certification Authorities" # 5. Complete the wizard
8

Verify HTTPS Setup

Test Kong Endpoints PowerShell
# PowerShell - Test Kong endpoints Invoke-RestMethod -Uri "https://kong-admin.local/status" -SkipCertificateCheck Invoke-WebRequest -Uri "https://kong-proxy.local" -SkipCertificateCheck # Browser - Open these URLs # https://kong-ui.local # https://kong-admin.local # https://kong-proxy.local
✅

Final Configuration Summary

Setup Complete

Your Kong API Gateway is now secured with HTTPS. All endpoints use encrypted connections with automated certificate management.

Next Steps:

  • Proceed to Guide 2 to configure your applications with Kong
  • Refer to Guide 3 if you encounter any issues
Service HTTPS URL Certificate Purpose
Kong Admin API https://kong-admin.local kong-admin-tls Configuration management
Kong Proxy https://kong-proxy.local kong-proxy-tls API Gateway (public facing)
Kong Manager UI https://kong-ui.local kong-ui-tls Web-based administration

Important Notes

  • PowerShell 7+: Required for -SkipCertificateCheck parameter
  • Self-signed certificates: Suitable for local development only
  • Production: Use proper CA-signed certificates (Let's Encrypt, etc.)
  • Certificate renewal: cert-manager handles this automatically
