HashiCorp Vault Enterprise Guide

Reproducible setup for Secure Secrets Management in Docker environments.

Docker Infrastructure

Ensure your vault.hcl listener points to the TLS files and ui = true is set.

docker-compose.yml
services:
  vault:
    image: hashicorp/vault:latest
    container_name: vault-enterprise
    ports: ["8200:8200"]
    volumes:
      - ./config:/vault/config:ro
      - ./data:/vault/data
      - ./tls:/vault/tls:ro
    cap_add: [IPC_LOCK]
    command: vault server -config=/vault/config/vault.hcl

Unseal Ceremony

Frequency: Only required after a container restart.
PowerShell / CMD
:: Initialize (Save Unseal Keys and Root Token!)
docker exec -e VAULT_ADDR='https://127.0.0.1:8200' -e VAULT_SKIP_VERIFY='true' -it vault-enterprise vault operator init

:: Unseal (Repeat 3 times with different keys)
docker exec -e VAULT_ADDR='https://127.0.0.1:8200' -e VAULT_SKIP_VERIFY='true' -it vault-enterprise vault operator unseal

Policies & Secrets

Using CMD ensures the HCL policy string is parsed correctly.

CMD (Command Prompt)
:: Create Policy
echo path "tenants/data/*" { capabilities = ["read"] } | docker exec -i -e VAULT_ADDR=https://127.0.0.1:8200 -e VAULT_SKIP_VERIFY=true vault-enterprise vault policy write tenant-reader -

:: Enable KV-V2 and Add Secret
docker exec -e VAULT_ADDR=https://127.0.0.1:8200 -e VAULT_SKIP_VERIFY=true vault-enterprise vault secrets enable -path=tenants kv-v2
docker exec -e VAULT_ADDR=https://127.0.0.1:8200 -e VAULT_SKIP_VERIFY=true vault-enterprise vault kv put tenants/WIPRO connectionString="Server=SQL_WIPRO;..."

AppRole Authentication

CMD
:: Enable AppRole
docker exec -e VAULT_ADDR=https://127.0.0.1:8200 -e VAULT_SKIP_VERIFY=true vault-enterprise vault auth enable approle

:: Bind Policy to Role
docker exec -e VAULT_ADDR=https://127.0.0.1:8200 -e VAULT_SKIP_VERIFY=true vault-enterprise vault write auth/approle/role/dotnet-api-role token_policies="tenant-reader"

:: Generate Credentials (Copy these for .NET)
docker exec -e VAULT_ADDR=https://127.0.0.1:8200 -e VAULT_SKIP_VERIFY=true vault-enterprise vault read auth/approle/role/dotnet-api-role/role-id
docker exec -e VAULT_ADDR=https://127.0.0.1:8200 -e VAULT_SKIP_VERIFY=true vault-enterprise vault write -f auth/approle/role/dotnet-api-role/secret-id

Vault UI Management

The GUI is available at https://127.0.0.1:8200. Log in with your Root Token.

UI ACTION Managing Secrets: Navigate to Secrets -> tenants. Click on a secret to create a new version, or Create Secret to add a new tenant.
UI ACTION Modifying Policies: Navigate to Policies. You can edit the tenant-reader HCL directly in the browser to add new paths.

.NET 9 Integration

Program.cs (VaultSharp v1.17.5.1)
var vaultClientSettings = new VaultClientSettings(uri, authMethod)
{
    PostProcessHttpClientHandlerAction = handler =>
    {
        if (handler is HttpClientHandler httpClientHandler)
        {
            httpClientHandler.ServerCertificateCustomValidationCallback =
                (message, cert, chain, sslPolicyErrors) => true;
        }
    }
};
builder.Services.AddSingleton<IVaultClient>(new VaultClient(vaultClientSettings));

Troubleshooting

  • Unterminated Quoted String: Use CMD instead of PowerShell for echo commands.
  • Task vs Result: Ensure you await the service call in your Controller.
  • Property Errors: For VaultSharp 1.17.x, use PostProcessHttpClientHandlerAction.
  • SSL Warning in UI: This is expected with self-signed certs. Click Advanced -> Proceed.
