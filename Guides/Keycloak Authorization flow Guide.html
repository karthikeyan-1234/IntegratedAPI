🔑 Token Types Explained

Access Token (JWT)

Lifetime: 5-15 minutes

Purpose: API Authorization

Contains: User claims, scopes

Refresh Token

Lifetime: Hours/days

Purpose: Get new access tokens

Storage: Secure HTTP-only cookie

ID Token (JWT)

Purpose: User authentication info

Contains: User profile data

Used for: Client-side user info

🔄 Angular Auth Interceptor

The interceptor automatically manages tokens for all HTTP requests:

// auth.interceptor.ts - Token Management intercept(req: HttpRequest, next: HttpHandler): Observable> { return from( // Refresh token if expiring in 30 seconds this.keycloakService.updateToken(30).then((refreshed) => { if (refreshed) console.log('Token refreshed'); }) ).pipe( switchMap(() => from(this.keycloakService.getToken())), switchMap(token => { if (token) { const authReq = req.clone({ setHeaders: { Authorization: `Bearer ${token}` } }); return next.handle(authReq); } this.authService.logout(); return next.handle(req); }) ); }

📞 Keycloak API Calls Summary

1. Authorization Request

Method: GET

Endpoint: /auth

Returns: Authorization code

2. Token Exchange

Method: POST

Endpoint: /token

Returns: Access, Refresh, ID tokens

3. UMA Permission Check

Method: POST

Endpoint: /token (uma-ticket)

Returns: Permission decision

4. Token Refresh

Method: POST

Endpoint: /token (refresh_token)

Returns: New access token

🏆 Best Practices Implemented

  • Silent Token Refresh: Automatic refresh 30 seconds before expiry
  • Resource Attributes: Declarative permission requirements
  • Centralized Auth Logic: Single filter handles all authorization
  • HTTPS Enforcement: In production (disabled in dev for testing)
  • Audience Validation: Multiple valid audiences supported
  • Proper Error Handling: Clear logs for auth failures
