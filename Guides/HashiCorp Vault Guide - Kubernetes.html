HashiCorp Vault on Kubernetes

Production‑style deployment inside Docker Desktop Kubernetes with secure routing and .NET integration.

📁 Manifests: C:\Users\mail2\source\repos\IntegratedAPP\IntegratedAPI\YMLs\vault

Architecture Overview

This guide deploys a single‑node Vault instance in the vault namespace, using a persistent volume for data. All manifests are stored under YMLs\vault\.
Target layout:
Docker Desktop Kubernetes Cluster
│
├── namespace: vault
│   ├── Vault Pod (StatefulSet‑ready)
│   ├── Vault Service (ClusterIP)
│   ├── PersistentVolumeClaim (2Gi)
│   └── AppRole secrets (Kubernetes secret)
│
└── namespace: default
    └── integratedapi pods → authenticate to Vault via AppRole

Prerequisites

  • Docker Desktop with Kubernetes enabled (Settings → Kubernetes → Enable)
  • kubectl installed and context set to docker-desktop
  • Helm (optional, but we'll use raw YAMLs for clarity)
  • PowerShell 7+ (for -SkipCertificateCheck later)
Verify context
kubectl config current-context   # should return docker-desktop

Deploy Vault to Kubernetes

Create the namespace and all required resources. Each manifest is shown with its filename; apply them in order.

3.1 Namespace

vault-namespace.yml
apiVersion: v1
kind: Namespace
metadata:
  name: vault
Apply
kubectl apply -f vault-namespace.yml

3.2 Persistent Volume Claim

vault-pvc.yml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: vault-pvc
  namespace: vault
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 2Gi
Apply
kubectl apply -f vault-pvc.yml

3.3 Vault Configuration (ConfigMap)

vault-configmap.yml
apiVersion: v1
kind: ConfigMap
metadata:
  name: vault-config
  namespace: vault
data:
  vault.hcl: |
    ui = true
    listener "tcp" {
      address       = "0.0.0.0:8200"
      tls_disable   = 1                       # TLS disabled inside cluster; use Ingress for TLS
    }
    storage "file" {
      path = "/vault/data"
    }
    api_addr = "http://vault-service.vault.svc.cluster.local:8200"
Apply
kubectl apply -f vault-configmap.yml

3.4 Deployment

vault-deployment.yml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: vault
  namespace: vault
spec:
  replicas: 1
  selector:
    matchLabels:
      app: vault
  template:
    metadata:
      labels:
        app: vault
    spec:
      containers:
      - name: vault
        image: hashicorp/vault:1.15
        args:
          - "server"
          - "-config=/vault/config/vault.hcl"
        ports:
          - containerPort: 8200
        volumeMounts:
          - name: vault-config
            mountPath: /vault/config
          - name: vault-storage
            mountPath: /vault/data
      volumes:
        - name: vault-config
          configMap:
            name: vault-config
        - name: vault-storage
          persistentVolumeClaim:
            claimName: vault-pvc
Apply
kubectl apply -f vault-deployment.yml

3.5 Service (ClusterIP)

vault-service.yml
apiVersion: v1
kind: Service
metadata:
  name: vault-service
  namespace: vault
spec:
  selector:
    app: vault
  ports:
    - port: 8200
      targetPort: 8200
  type: ClusterIP
Apply
kubectl apply -f vault-service.yml
Verify everything is running:
kubectl get pods -n vault (wait for Running)
kubectl get svc -n vault

Initialize Vault

One‑time only. After deployment, Vault is sealed and uninitialized. Run this exactly once. Store the 5 unseal keys and root token securely.
Initialize
kubectl exec -it -n vault deploy/vault -- vault operator init

Example output (save everything!):

Unseal Key 1: wJ6iZz8sxPq1...
Unseal Key 2: LkH9fR3tG7...
...
Initial Root Token: hvs.ABC123...

Unseal Ceremony

Vault starts sealed after every restart. Use three different unseal keys to unseal.

Unseal (run 3 times with different keys)
kubectl exec -it -n vault deploy/vault -- vault operator unseal

After third key, status shows Sealed: false. Then log in with the root token:

Login
kubectl exec -it -n vault deploy/vault -- vault login

AppRole Authentication

Enable AppRole, create a policy, and generate credentials for .NET.

6.1 Enable AppRole

Command
kubectl exec -n vault deploy/vault -- vault auth enable approle

6.2 Create a policy (using a file to avoid quoting issues).

Create policy.hcl locally and apply
# On your machine, create a file policy.hcl:
cat < policy.hcl
path "secret/data/integratedapi/*" {
  capabilities = ["read"]
}
EOF

# Copy file into the pod
kubectl cp policy.hcl vault/<vault-pod-name>:/tmp/policy.hcl

# Write policy
kubectl exec -n vault deploy/vault -- vault policy write integratedapi-policy /tmp/policy.hcl

6.3 Create role and bind policy

Command
kubectl exec -n vault deploy/vault -- vault write auth/approle/role/integratedapi-role token_policies="integratedapi-policy"

6.4 Retrieve Role ID and Secret ID (example values shown – replace with your own)

Get Role ID
kubectl exec -n vault deploy/vault -- vault read auth/approle/role/integratedapi-role/role-id

# Example output (hypothetical, replace with actual):
Role ID: 8b3d9e2a-1f4c-4e7b-9a6d-3f2c1a8e5d7b
Generate Secret ID
kubectl exec -n vault deploy/vault -- vault write -f auth/approle/role/integratedapi-role/secret-id

# Example output (hypothetical, replace with actual):
Secret ID: 6a2c4f8e-9b1d-4a3c-8e5f-2d7b9c1a3e6d

6.5 Store credentials as Kubernetes secret (optional but recommended)

Create secret
kubectl create secret generic vault-approle \
  --namespace default \
  --from-literal=role-id=8b3d9e2a-1f4c-4e7b-9a6d-3f2c1a8e5d7b \
  --from-literal=secret-id=6a2c4f8e-9b1d-4a3c-8e5f-2d7b9c1a3e6d

Accessing Vault (Routing)

Once Vault is running, you need to reach it from your applications and for administration. Below are the common methods.

Internal cluster access

The service vault-service.vault.svc.cluster.local:8200 is resolvable inside the cluster. Your .NET app can use this URL directly.

Local port‑forward (for development)

Port‑forward to localhost:8200
kubectl port-forward -n vault svc/vault-service 8200:8200

Then open http://localhost:8200 to access the Vault UI (no TLS because we disabled it in config).

Ingress (TLS‑secured external access)

If you need to expose Vault outside the cluster with HTTPS, create an Ingress (requires an ingress controller, e.g., NGINX Ingress). Example:

vault-ingress.yml (optional)
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: vault-ingress
  namespace: vault
  annotations:
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
spec:
  ingressClassName: nginx
  tls:
  - hosts:
    - vault.local
    secretName: vault-tls   # you must create this secret with cert/key
  rules:
  - host: vault.local
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: vault-service
            port:
              number: 8200

Add 127.0.0.1 vault.local to your hosts file and access https://vault.local.

For production, always enable TLS on Vault itself (set tls_cert_file/tls_key_file in vault.hcl) and use a proper CA.

.NET 9 Integration (VaultSharp)

Add the VaultSharp NuGet package. Example configuration in Program.cs:

Program.cs
using VaultSharp;
using VaultSharp.V1.AuthMethods.AppRole;

// Replace with your actual RoleId/SecretId (or load from k8s secrets)
// HYPOTHETICAL EXAMPLE – use your own values from step 6.4
string roleId = "8b3d9e2a-1f4c-4e7b-9a6d-3f2c1a8e5d7b";
string secretId = "6a2c4f8e-9b1d-4a3c-8e5f-2d7b9c1a3e6d";

var authMethod = new AppRoleAuthMethodInfo(roleId, secretId);
var vaultClientSettings = new VaultClientSettings(
    "http://vault-service.vault.svc.cluster.local:8200",
    authMethod)
{
    PostProcessHttpClientHandlerAction = handler =>
    {
        if (handler is HttpClientHandler httpClientHandler)
        {
            // Bypass TLS verification if using self-signed certs (dev only)
            httpClientHandler.ServerCertificateCustomValidationCallback =
                (message, cert, chain, errors) => true;
        }
    }
};

builder.Services.AddSingleton<IVaultClient>(new VaultClient(vaultClientSettings));

Troubleshooting

  • Pod fails to start: "error reading config file" – Ensure the ConfigMap mount path matches /vault/config/vault.hcl. Check logs with kubectl logs -n vault <pod>.
  • Vault stays sealed after unseal commands – You must run vault operator unseal three times with different keys. Verify status: kubectl exec -n vault deploy/vault -- vault status.
  • Permission denied when reading secrets – Confirm the policy is attached to the role and the AppRole has the correct token_policies. Also ensure secrets exist under the correct path.
  • Connection refused from .NET app – Check that the service name and namespace are correct: vault-service.vault.svc.cluster.local. Test from a temporary pod: kubectl run -it --rm test --image=curlimages/curl -- curl http://vault-service.vault:8200/v1/sys/health.
  • Browser shows blank page / cannot connect – If using port-forward, ensure it’s running. If using Ingress, verify TLS secret and hosts file.
  • "Vault is sealed" after cluster restart – Normal. Redeploy or just unseal again using the saved keys. The PVC persists the data.
