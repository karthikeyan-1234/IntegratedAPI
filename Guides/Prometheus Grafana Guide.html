✅ Prerequisites

Ensure you have the following before starting:

Required Software

  • Docker Desktop with Kubernetes enabled
  • kubectl command-line tool installed
  • PowerShell with Administrator privileges
  • .NET 10 SDK installed
  • Visual Studio 2022 or VS Code

    • Verify Kubernetes is Running

    PowerShell Command
    kubectl version --short
    You should see both client and server versions. If not, enable Kubernetes in Docker Desktop settings.

    Your .NET API Deployment Options

    You can run your .NET API in two ways:

    Option 1: Running from Visual Studio (Development)

    ✅ Recommended for development and testing

    • Run your API directly from Visual Studio
    • API runs on https://localhost:7216
    • Prometheus scrapes via host.docker.internal:7216
    • Easy debugging and code changes

    Option 2: Deployed to Kubernetes (Production-like)

    ✅ Recommended for production testing

    • Deploy your API as a Kubernetes service
    • API accessible via service name in cluster
    • Prometheus scrapes via integratedapi-service.default.svc.cluster.local:7080
    • Tests full Kubernetes networking

    Your .NET API Configuration

    Important: Your .NET API is already configured with Prometheus metrics! Based on your Program.cs, you have:
    • app.UseHttpMetrics() - Tracks HTTP request metrics
    • app.MapMetrics("/metrics") - Exposes metrics endpoint
    • app.MapHealthChecks("/health") - Health check endpoint
    • app.MapHealthChecks("/ready") - Readiness endpoint
    • app.MapHealthChecks("/live") - Liveness endpoint

    🌐 Hosts File Configuration

    Configure your Windows hosts file to access Prometheus and Grafana using friendly domain names instead of localhost:port.

    Step 1: Open Hosts File as Administrator

    PowerShell (Run as Administrator)
    notepad C:\Windows\System32\drivers\etc\hosts

    Step 2: Add Entries

    Add the following lines to the end of the hosts file:

    C:\Windows\System32\drivers\etc\hosts
    # Prometheus & Grafana for Kubernetes Monitoring 127.0.0.1 prometheus.local 127.0.0.1 grafana.local

    Step 3: Save and Close

    1. Save the file (Ctrl+S)
    2. Close Notepad
    3. No restart required - changes are immediate

    Step 4: Verify Hosts File

    PowerShell Command
    ping prometheus.local ping grafana.local
    Both should resolve to 127.0.0.1 and you'll see "Reply from 127.0.0.1"

    Access URLs After Configuration

    After deploying to Kubernetes, you'll access:

    Prometheus: http://prometheus.local:30090
    Grafana: http://grafana.local:30300
    Troubleshooting: If you can't edit the hosts file:
    • Make sure you're running PowerShell/Notepad as Administrator
    • Check if antivirus is blocking hosts file modifications
    • Verify the file is not read-only (right-click → Properties)

    🏗️ Architecture Overview

    Complete Monitoring Stack

    📱 Your .NET API
    Option 1: localhost:7216 (Visual Studio)
    Option 2: integratedapi-service.default.svc:7080 (K8s)

    Scrapes /metrics every 15s

    NodePort: 30090 → prometheus.local:30090

    Visualizes metrics

    Data Flow Explanation

    1. Metrics Generation: Your .NET API generates Prometheus metrics automatically through the prometheus-net.AspNetCore library
    2. Metrics Exposure: Metrics are exposed at the /metrics endpoint
    3. Scraping (Visual Studio): Prometheus scrapes host.docker.internal:7216/metrics every 15 seconds
    4. Scraping (Kubernetes): Prometheus scrapes integratedapi-service.default.svc.cluster.local:7080/metrics
    5. Storage: Prometheus stores time-series data for 7 days (configurable via --storage.tsdb.retention.time)
    6. Querying: Grafana queries Prometheus using PromQL via internal service DNS
    7. Visualization: Grafana displays metrics in dashboards accessible at http://grafana.local:30300

    Why This Configuration?

    Kubernetes vs Docker Compose: This guide uses Kubernetes because:
    • ✅ Production-grade deployment practices
    • ✅ RBAC (Role-Based Access Control) security
    • ✅ ConfigMap-based configuration management
    • ✅ Health checks and automatic restarts
    • ✅ Service discovery within cluster
    • ✅ Easy scaling capabilities
    • ✅ Declarative configuration with kubectl

    NodePort vs ClusterIP

    NodePort Services: Prometheus and Grafana use NodePort to expose services externally
    • Prometheus: Port 30090 (mapped from internal 9090)
    • Grafana: Port 30300 (mapped from internal 3000)

    ClusterIP Service: Your API (if deployed to K8s) uses ClusterIP for internal cluster communication

    1 Kubernetes Deployment with kubectl

    Step 1: Navigate to Your Project

    PowerShell (Administrator)
    cd C:\Users\mail2\source\repos\IntegratedAPP\IntegratedAPI\Prometheus-Grafana
    Alternatively, clone from GitHub:
    PowerShell
    git clone https://github.com/karthikeyan-1234/IntegratedAPI.git cd IntegratedAPI\Prometheus-Grafana

    Step 2: Create the Monitoring Namespace

    PowerShell Command
    kubectl create namespace monitoring
    Expected output: namespace/monitoring created

    Step 3: Deploy Prometheus Configuration

    Apply the Prometheus configuration ConfigMap:

    PowerShell Command
    kubectl apply -f prometheus-config.yml
    Expected output: configmap/prometheus-config created
    Configuration Details: The prometheus-config.yml contains scrape targets for:
    • integrated-api: Your .NET API (both localhost and K8s service options)
    • prometheus: Prometheus itself for internal metrics
    • kubernetes-apiservers: K8s API server metrics
    • kubernetes-nodes: K8s node metrics

    Step 4: Deploy Prometheus with RBAC

    PowerShell Command
    kubectl apply -f prometheus-deploy.yml
    Expected output (6 resources created):
    • namespace/monitoring created (or already exists)
    • deployment.apps/prometheus created
    • serviceaccount/prometheus-service-account created
    • clusterrole.rbac.authorization.k8s.io/prometheus-cluster-role created
    • clusterrolebinding.rbac.authorization.k8s.io/prometheus-cluster-role-binding created
    • service/prometheus-service created

    Step 5: Deploy Grafana

    PowerShell Command
    kubectl apply -f grafana-deploy.yml
    Expected output (4 resources created):
    • deployment.apps/grafana created
    • configmap/grafana-datasources created
    • configmap/grafana-dashboards created
    • service/grafana-service created

    Step 6: Verify All Deployments

    PowerShell Command
    kubectl get all -n monitoring
    What to expect:
    • ✅ 2 pods (prometheus-xxx and grafana-xxx) in Running state
    • ✅ 2 services (prometheus-service and grafana-service) with NodePort type
    • ✅ 2 deployments (prometheus and grafana) with 1/1 ready
    • ✅ 2 replicasets (one for each deployment)

    Step 7: Watch Pods Until Ready

    Monitor the pods until they're fully running:

    PowerShell Command
    kubectl get pods -n monitoring -w
    Press Ctrl+C to stop watching. Wait until both pods show 1/1 in the READY column and Running status.

    Step 8: Verify Services and NodePorts

    PowerShell Command
    kubectl get svc -n monitoring
    You should see:
    • prometheus-service - Type: NodePort, Port: 9090:30090/TCP
    • grafana-service - Type: NodePort, Port: 3000:30300/TCP

    Step 9: View Detailed Pod Information

    PowerShell Commands
    # View Prometheus pod details kubectl describe pod -n monitoring -l app=prometheus # View Grafana pod details kubectl describe pod -n monitoring -l app=grafana

    Step 10: Check ConfigMaps

    PowerShell Command
    kubectl get configmaps -n monitoring
    ✅ Deployment Complete! Your monitoring stack is now running in Kubernetes.

    2 Verify Prometheus is Scraping Metrics

    Step 1: Access Prometheus Web UI

    Open your browser and navigate to:

    URL: http://prometheus.local:30090
    Alternative URLs:
    • http://localhost:30090
    • http://127.0.0.1:30090

    Step 2: Check Scrape Targets

    1. In Prometheus UI, click on Status in the top menu
    2. Select Targets from the dropdown
    3. Look for the following targets and their status:
    Expected Targets:
    • integrated-api (1/1 up) - ● UP (green)
    • prometheus (1/1 up) - ● UP (green)
    • kubernetes-apiservers - ● UP (green)
    • kubernetes-nodes - ● UP (green)
    If "integrated-api" target is DOWN:
    • Option 1 (Visual Studio): Make sure your .NET API is running on https://localhost:7216
    • Option 2 (Kubernetes): Make sure your API is deployed with service name integratedapi-service in default namespace

    Step 3: Query Metrics

    Test that Prometheus is collecting metrics from your API:

    1. Go back to the Prometheus home page (click "Prometheus" logo)
    2. In the query box, enter:
    PromQL Query
    http_requests_received_total
    1. Click Execute
    2. Switch to the Graph tab to see visual representation
    3. You should see metrics data (even if values are zero initially)
    Available .NET Metrics to Test:
    • http_requests_received_total - Total HTTP requests
    • http_request_duration_seconds - Request duration histogram
    • http_requests_in_progress - Active requests
    • process_private_memory_bytes - Process memory usage
    • process_cpu_seconds_total - CPU time used
    • dotnet_total_memory_bytes - .NET memory metrics
    • up - Shows all targets (1 = up, 0 = down)

    Step 4: Test Connectivity from Prometheus Pod

    If the target shows DOWN, test connectivity from inside the Prometheus pod:

    For Visual Studio Deployment:

    PowerShell Commands
    # Get Prometheus pod name $podName = kubectl get pods -n monitoring -l app=prometheus -o jsonpath="{.items[0].metadata.name}" # Test connection to localhost API kubectl exec -n monitoring $podName -- wget -O- --no-check-certificate https://host.docker.internal:7216/metrics

    For Kubernetes Deployment:

    PowerShell Command
    kubectl exec -n monitoring $podName -- wget -O- http://integratedapi-service.default.svc.cluster.local:7080/metrics
    If successful, you'll see Prometheus metrics output (text format with # comments and metric lines).

    Step 5: Verify Scrape Configuration

    PowerShell Command
    kubectl get configmap prometheus-config -n monitoring -o yaml

    This shows your current Prometheus scrape configuration.

    3 Grafana Configuration

    Step 1: Access Grafana

    Open your browser and navigate to:

    URL: http://grafana.local:30300

    Default Credentials:
    Username: admin
    Password: admin123
    Alternative URLs:
    • http://localhost:30300
    • http://127.0.0.1:30300
    Grafana may ask you to change the password on first login. You can:
    • Change it to a new password
    • Click "Skip" to keep using admin123

    Step 2: Verify Pre-Configured Data Source

    The Prometheus data source is already configured via ConfigMap! To verify:

    1. Click the ⚙️ Configuration (gear icon) in the left sidebar
    2. Select Data Sources
    3. You should see Prometheus listed with a green checkmark
    4. Click on it to view the configuration:
      • Name: Prometheus
      • Type: Prometheus
      • URL: http://prometheus-service.monitoring.svc.cluster.local:9090
      • Access: Server (default/proxy)
      • Scrape interval: 5s
      • Query timeout: 60s
    5. Scroll down and click Save & Test
    You should see a green notification: "Data source is working"

    Understanding the Auto-Configuration

    The data source is automatically provisioned through the grafana-datasources ConfigMap defined in grafana-deploy.yml:
    • ✅ Uses Kubernetes internal DNS for service discovery
    • ✅ No manual configuration needed
    • ✅ Automatically set as default data source
    • ✅ Configured for optimal performance (5s interval, 60s timeout)

    Step 3: Explore Prometheus Data

    1. Click Explore (compass icon) in the left sidebar
    2. Ensure Prometheus is selected as the data source (top dropdown)
    3. In the Metrics browser, start typing: http_
    4. You should see auto-complete suggestions with all available HTTP metrics
    5. Select http_requests_received_total and click Run query
    You should see metric data and a graph. This confirms Grafana can query Prometheus successfully!

    Option 2: Create Custom Dashboard

    Build your own dashboard with specific metrics tailored to your API:

    Creating a New Dashboard

    1. Click the + icon in the left sidebar
    2. Select Create Dashboard
    3. Click Add visualization
    4. Select Prometheus as the data source

    Panel 1: HTTP Request Rate

    PromQL Query
    rate(http_requests_received_total[1m])

    Panel Configuration:

    • Title: HTTP Request Rate
    • Description: Requests per second
    • Unit: reqps (requests per second)
    • Visualization: Time series
    • Legend: Show - displays labels
    • Click Apply to save

    Panel 2: Request Duration (95th Percentile)

    PromQL Query
    histogram_quantile(0.95, rate(http_request_duration_seconds_bucket[5m])) * 1000

    Panel Configuration:

    • Title: Request Duration (P95)
    • Unit: ms (milliseconds)
    • Visualization: Time series or Gauge
    • Thresholds:
      • Green: 0-200ms
      • Yellow: 200-500ms
      • Red: >500ms
    • Click Apply

    Panel 3: Memory Usage

    PromQL Query
    process_private_memory_bytes / 1024 / 1024

    Panel Configuration:

    • Title: Process Memory Usage
    • Unit: MiB (Mebibytes)
    • Visualization: Time series
    • Fill opacity: 20%
    • Click Apply

    Panel 4: CPU Usage

    PromQL Query
    rate(process_cpu_seconds_total[1m]) * 100

    Panel Configuration:

    • Title: CPU Usage
    • Unit: percent (0-100)
    • Visualization: Gauge or Time series
    • Max value: 100
    • Click Apply
