1. Prerequisites

Required Software

  • Docker Desktop with Kubernetes enabled
  • kubectl CLI installed and configured
  • Git (to clone the repository)
  • Administrator access (for editing hosts file)

Enable Kubernetes in Docker Desktop

1 Open Docker Desktop → Settings → Kubernetes → Enable Kubernetes
2 Wait for Kubernetes to start (green icon in bottom-left)

Verify Installation

kubectl cluster-info kubectl get nodes
✅ You should see your Docker Desktop node in a Ready state

2. Configure Hosts File

Location: C:\Windows\System32\drivers\etc\hosts (Windows)

Add ELK Stack Entries

1 Open Notepad as Administrator
2 Open the hosts file from the location above
3 Add the following entries:
# ELK Stack Services 127.0.0.1 elasticsearch.local 127.0.0.1 kibana.local 127.0.0.1 logstash.local
4 Save the file

Verify Hosts File

ping elasticsearch.local
✅ Should resolve to 127.0.0.1

3. Deploy NGINX Ingress Controller

The NGINX Ingress Controller routes external traffic to your Kubernetes services based on hostnames.

Deploy NGINX

kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/controller-v1.10.1/deploy/static/provider/cloud/deploy.yaml

Wait for NGINX to be Ready

kubectl wait --namespace ingress-nginx \ --for=condition=ready pod \ --selector=app.kubernetes.io/component=controller \ --timeout=120s

Verify NGINX Deployment

kubectl get pods -n ingress-nginx
✅ The ingress-nginx-controller pod should be in Running state

4. Deploy ELK Stack

GitHub Repository:
📁 View ELK YML Files on GitHub

Clone the Repository

git clone https://github.com/karthikeyan-1234/IntegratedAPI.git cd IntegratedAPI/ELk

Pre-pull Docker Images

⚠️ Docker Desktop may have issues pulling images during deployment. Pre-pull them to avoid failures.
docker pull docker.elastic.co/elasticsearch/elasticsearch:8.11.0 docker pull docker.elastic.co/logstash/logstash:8.11.0 docker pull docker.elastic.co/kibana/kibana:8.11.0

Deploy in Order

1 Create Namespace
kubectl apply -f namespace.yml
2 Deploy Elasticsearch
kubectl apply -f elasticsearch.yml # Wait for Elasticsearch to be ready kubectl wait --for=condition=ready pod -l app=elasticsearch -n elk --timeout=300s
3 Deploy Logstash
kubectl apply -f logstash.yml # Wait for Logstash to be ready kubectl wait --for=condition=ready pod -l app=logstash -n elk --timeout=180s
4 Deploy Kibana
kubectl apply -f kibana.yml # Monitor Kibana startup (it takes 1-2 minutes) kubectl get pods -n elk -w

Verify All Pods Running

kubectl get pods -n elk
✅ All three pods should show 1/1 Running

5. Verification & Testing

Check Services

kubectl get svc -n elk kubectl get ingress -n elk

Test Elasticsearch

# PowerShell Invoke-WebRequest -Uri http://elasticsearch.local/_cat/indices?v

Test Logstash

# PowerShell - Send test log Invoke-WebRequest -Uri http://logstash.local/ ` -Method Post ` -ContentType "application/json" ` -Body '{"message":"test log","level":"info"}'
✅ Should return StatusCode: 200 with content "ok"

Verify Log in Elasticsearch

# Wait a few seconds, then check Invoke-WebRequest -Uri "http://elasticsearch.local/logstash-*/_search?pretty" | Select-Object -ExpandProperty Content
✅ You should see your test log in the response

Access Kibana

Open your browser and navigate to: http://kibana.local

6. Kibana Configuration

Create Data View

1 In Kibana, click the hamburger menu (☰) → Management → Stack Management
2 Under Kibana, click Data Views
3 Click Create data view
4 Configure the data view:
Field Value
Name Logstash Logs
Index pattern logstash-*
Timestamp field @timestamp
5 Click Save data view to Kibana

View Logs in Discover

1 Click hamburger menu (☰) → Analytics → Discover
2 Select Logstash Logs data view
3 You should see your logs!

Customize Columns (Optional)

Click the + button next to these fields to add them as columns:
  • @timestamp
  • level
  • message
  • fields.RequestPath (for API endpoints)
  • fields.StatusCode
  • host.ip
Click Save to save your customized view.

7. .NET API Integration

appsettings.json Configuration

Ensure your appsettings.json or appsettings.Development.json contains:
{ "Logging": { "LogLevel": { "Default": "Debug", "Microsoft": "Warning", "Microsoft.Hosting.Lifetime": "Information" }, "Logstash": { "Url": "http://logstash.local/" } } }

Test .NET API Logging

1 Start your .NET API from Visual Studio
2 Call the diagnostic endpoint (replace <port> with your API port):
# PowerShell Invoke-WebRequest -Uri http://localhost:<port>/diagnostics/logs
3 Wait a few seconds, then check Elasticsearch:
Invoke-WebRequest -Uri "http://elasticsearch.local/logstash-*/_search?pretty&size=20&sort=@timestamp:desc" | Select-Object -ExpandProperty Content
4 View logs in Kibana Discover

Filter API Logs in Kibana

In Kibana Discover search bar, enter: fields.Application:"IntegratedAPI"
✅ All logs from your controllers using ILogger<T> will now appear in Kibana with proper log levels (Debug, Info, Warning, Error, etc.)

8. Troubleshooting

Pod Not Starting / ImagePullBackOff

Problem: Pods stuck in ImagePullBackOff or Pending
1 Check pod status:
kubectl describe pod -l app=elasticsearch -n elk
2 Pre-pull images manually:
docker pull docker.elastic.co/elasticsearch/elasticsearch:8.11.0 docker pull docker.elastic.co/logstash/logstash:8.11.0 docker pull docker.elastic.co/kibana/kibana:8.11.0
3 Delete and recreate the deployment:
kubectl delete -f elasticsearch.yml kubectl apply -f elasticsearch.yml

Logstash CrashLoopBackOff

Problem: Logstash pod keeps restarting
1 Check logs:
kubectl logs -n elk -l app=logstash --tail=50
2 Ensure the YAML file is correct (no config file mount issues)

Cannot Access Services (http://elasticsearch.local not working)

Problem: Services not accessible via browser
1 Verify NGINX Ingress Controller is running:
kubectl get pods -n ingress-nginx
2 Check hosts file entries are correct
3 Verify ingress resources:
kubectl get ingress -n elk kubectl describe ingress elasticsearch-ingress -n elk
4 As a workaround, use port-forwarding:
kubectl port-forward -n elk svc/elasticsearch 9200:9200 kubectl port-forward -n elk svc/logstash 5001:5001 kubectl port-forward -n elk svc/kibana 5601:5601
Then access via localhost:9200, localhost:5001, localhost:5601

No Logs Appearing in Kibana

Problem: Logs not visible in Kibana Discover
1 Check if indices exist in Elasticsearch:
Invoke-WebRequest -Uri http://elasticsearch.local/_cat/indices?v
2 Verify data view index pattern is correct (logstash-*)
3 Check time range in Kibana (top-right corner) - set to "Last 15 minutes" or "Today"
4 Send a test log and verify it reaches Elasticsearch:
Invoke-WebRequest -Uri http://logstash.local/ ` -Method Post ` -ContentType "application/json" ` -Body '{"message":"troubleshooting test","level":"info"}' # Wait 10 seconds Start-Sleep -Seconds 10 # Query Elasticsearch Invoke-WebRequest -Uri "http://elasticsearch.local/logstash-*/_search?q=troubleshooting&pretty"

.NET API Logs Not Appearing

Problem: .NET API logs not showing in Kibana
1 Verify Logstash URL in appsettings.json: "Url": "http://logstash.local/"
2 Check API can reach Logstash:
Invoke-WebRequest -Uri http://localhost:<api-port>/diagnostics/logstash
3 Verify Serilog is configured correctly in Program.cs (using ElasticsearchJsonFormatter)
4 Check console output in Visual Studio for Serilog errors

Useful Diagnostic Commands

# View all resources in elk namespace kubectl get all -n elk # Check pod logs kubectl logs -n elk <pod-name> # Describe a pod for detailed status kubectl describe pod -n elk <pod-name> # Check events in namespace kubectl get events -n elk --sort-by='.lastTimestamp' # Restart a deployment kubectl rollout restart deployment/logstash -n elk # Delete all ELK resources and start fresh kubectl delete namespace elk
